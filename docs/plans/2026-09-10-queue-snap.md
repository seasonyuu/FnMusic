# 播放列表滚动与吸附改造计划

## 目标

根据用户提供的两段 Apple Music 录屏（14.38 秒长历史、26.14 秒单条历史），改善历史记录与当前歌曲分界处的停靠感。保留连续滚动、队列排序以及现有歌曲信息下拉关闭播放器的操作。

用户确认后已完成首版实施；以下保留交互依据与验收要求，文末记录实现结果。

## 录屏观察

时间为近似位置。录屏中的指针提示不能提供可靠的触摸释放时刻或速度，因此以下区分可见行为与实现推断。

| 时间 | 可见行为 | 含义 |
| --- | --- | --- |
| 0–2 秒 | 当前歌曲位于顶部；下拉露出少量历史记录；随后回到原位 | 当前歌曲顶部位置是明显的停靠位置 |
| 3–4.5 秒 | 再次出现短距离历史预览并回到当前歌曲 | 该回位行为具有重复性 |
| 5.5–7 秒 | 较大幅度下拉进入历史，当前歌曲随内容向下离开视口 | 历史可连续浏览，不能无条件拉回当前歌曲 |
| 7–8.5 秒 | 从历史返回后，当前歌曲重新停在顶部 | 从历史返回时也需要稳定的分界位置 |
| 9–14.38 秒 | 继续浏览历史；历史标题保持在顶部，歌曲在下面滚动 | 历史标题需要吸顶，历史内部仍应自由滚动 |

整个过程中底部播放控制保持原位，移动的是列表内容。当前歌曲封面、文字、操作按钮以及播放模式区域一起移动。

补充录屏（15:40:08，26.14 秒）提供了新的边界条件：

| 时间 | 可见行为 | 对计划的修正 |
| --- | --- | --- |
| 约 1–3 秒 | 展开单条历史后可以停留，当前歌曲紧随历史下方，待播列表继续填充下面的视口 | 少量历史也有可停留的展开位置，不能一律回到当前歌曲 |
| 约 3–10 秒 | 反复拖动，出现历史完整展开与当前歌曲回到顶部的落点 | 需要区分两个相邻的内容边界，不能只设无条件回位规则 |
| 约 11–15 秒及之后 | 当前歌曲滚出顶部，播放模式栏停靠顶部，待播歌曲占据更多空间 | 需要覆盖当前歌曲区域收起后的停靠与吸顶交接 |
| 约 24–26 秒 | 当前歌曲重新稳定显示在顶部 | 当前歌曲顶部仍是主要落点之一 |

历史不足一屏时没有把它强行扩成整屏，也没有把当前歌曲推到屏幕底部。历史、当前歌曲、播放模式、待播歌曲保持自然紧接的纵向布局。

两段录屏支持多个内容分界处存在稳定落点，但不能仅凭视频确定每个落点都由自定义 snap 实现：历史展开位置可能同时是自然滚动起点，播放模式停留涉及 sticky 行为。改造应复现结果，避免对已有边界回弹再叠加一层吸附。没有证据支持逐行吸附；指针提示也不足以还原精确释放速度和时刻。

## 改造前实现

入口：`feature/music/src/main/java/com/seasonyuu/fnmusic/feature/music/MusicUi.kt` 的 `QueuePlayerContent`。

- 已使用一条 `LazyColumn` 连续排列历史、当前歌曲、播放模式与待播队列。
- `queue-current` 是当前歌曲的稳定 key；首次进入通过 `currentHeaderIndex` 定位，历史默认在视口上方。
- 尚未定义用户滚动结束时的吸附策略，当前可停在只露出部分历史的中间位置。
- `queue-modes` 已吸顶；`history-title` 目前是普通 item。
- 当前歌曲信息已有整页下拉关闭手势；队列内还有横滑、排序及边缘自动滚动，需要区分手势所有权。

## 改造步骤

### 1. 定义随内容测量的停靠位置

以同一条列表中的内容边界定义三个可观察状态，不建立固定高度的三页分页：

- H：历史展开，历史内容起点到达视口顶部。少量历史直接完整展示，下面自然接当前歌曲和待播队列；大量历史仍允许在历史内部自由滚动。
- C：当前歌曲顶部与列表可视顶部对齐，历史隐藏在上方。
- Q：当前歌曲已滚出顶部，播放模式栏到达顶部；继续向待播深处滚动时保持正常吸顶与自由滚动。

H 到 C 的距离由历史标题、实际历史行高及分隔间距决定；C 到 Q 的距离由当前歌曲信息及其间距决定。不得为少量历史填充整屏高度。无历史时不创建 H。

拖动期间保持跟手，释放后结合当前位置、方向、速度及预计落点决定相邻边界是否吸附。轻微试探可以回到出发边界；明确向另一边界移动时可以停在目标边界，即使历史只有一条。历史深处和待播队列深处保留自由滚动，不强拉回远处锚点。

以当前位置所在区段和相邻边界判断目标，避免全局选择最近的锚点。为往返切换设置适度滞回，避免在边界附近抖动。把距离与速度权重集中配置，在 AVD 上调节，不从录屏臆造精确参数。

先确认 H 自然边界及 Q 原有吸顶能够完成的行为，只对尚缺少的停靠补充动画，防止重复回弹。动画期间新的触摸优先。

### 2. 接入滚动收尾

在列表滚动层统一处理惯性与最终落点；避免在普通惯性结束之后再启动明显的第二段回位。

覆盖慢拖、快速甩动和近零速度释放。新的触摸必须立即打断吸附，不得与用户抢滚动。只在用户浏览滚动结束时评估，初始化定位、无障碍滚动、排序自动滚动、切歌和布局变化不能意外触发吸附。

以稳定 key 解析锚点，避免历史插入后使用过期 index。浏览历史或待播深处时，不为了吸附强制跳回不可见的当前歌曲。

### 3. 历史标题吸顶

让“播放记录 / 清空”在历史浏览区域顶部保持可见；回到当前歌曲锚点后应退出。需处理它与现有播放模式吸顶区域的交接，不能让历史标题继续覆盖当前歌曲。

保持历史、当前歌曲、待播队列为同一条连续内容，不引入互相独立的滚动列表。

### 4. 手势与状态协调

- 从当前歌曲信息或下拉把手开始：沿用用户已确认的整页下拉关闭，列表吸附不介入。
- 从历史或队列内容开始：滚动列表并在适用时吸附，不关闭播放器。
- 排序、排序边缘自动滚动及横滑操作期间不运行吸附。
- 当前歌曲封面继续跟随同一个内容坐标，避免吸附时封面与文字分离。
- 新播放会话回到当前歌曲；普通切歌或历史变化保持合理浏览位置。
- 清空历史、队列为空及横竖屏切换时重新计算有效锚点，取消过期动画。

### 5. 验证与调参

先验证 H/C/Q 三个内容边界及短历史自然高度，再完成滚动收尾和历史标题吸顶交接，最后统一调节运动曲线。

验证场景：

1. 从 C 慢速短拉：拖动期间连续跟手；根据意图回 C 或到 H，单条历史也能稳定展开。
2. 长拉和快速下甩：可进入历史且能访问全部历史歌曲。
3. H/C/Q 往返：在内容分界附近稳定停靠；继续进入待播深处时不强制停 Q。
4. 吸附期间重新触摸：动画立即让出控制。
5. 当前歌曲信息下拉关闭、短拖回弹及轻点返回保持正常。
6. 队列内部滚动、横滑和排序不触发意外吸附。
7. 无历史、1 条、2–3 条、恰好接近一屏及长历史；验证没有人为撑满历史的空白；同时覆盖空待播队列、切歌及清空历史。
8. 20:9 竖屏、短横屏及大屏；底部控制固定，标题无重叠，封面与页头一致移动。

已有 `historyPullMovesRealCoverWithHeaderAndCanReachEveryHistoryRow` 在松手后断言短拉位移保留，需要改成拖动期间检查连续位移，再分别验证短拉吸附与长拉进入历史，避免旧断言阻止新的交互行为。

验收以相同手势下的前后录屏对比为主，配合锚点落点、手势取消与历史可达性的自动化测试。精确阈值和动画时长在实现验证后记录。

## 实现记录

- 新增 `QueueSnapBehavior.kt`，把停靠选择与滚动动画从页面中独立出来。
- 使用列表内容坐标计算 H/C/Q。历史尺寸与界面共用常量，并按布局像素取整；当前歌曲区域高度由布局测量获得，适应横竖屏差异。
- 使用原生衰减预测释放落点。基础捕获范围为 `min(144dp, 视口高度 × 22%)`；历史能完整放入视口时，H/C 之间扩大至覆盖相邻边界的中点，避免少量历史停在无意义的中间位置。这个扩展不作用于待播歌曲深处。
- 相邻位置采用 55% 的切换滞回。较长距离保留衰减接近过程，随后连续进入无回弹的临界阻尼弹簧（刚度 400）；新的触摸由列表滚动互斥机制立即中断动画。
- 历史标题吸顶，并在当前歌曲到达顶部时退出；历史行裁剪在标题下方，避免文字重叠。视口过矮时沿用模式栏的策略，禁用吸顶以保留歌曲操作空间。
- 队列排序与横滑期间禁用吸附；内容身份、测量高度或视口变化会终止过期的吸附。初始化与程序化滚动不经过用户 fling 收尾。
- 上述参数是本项目初始调参值，不是对 Apple Music 内部参数的还原。

验证覆盖：停靠规则单元测试；单条历史 H/C/Q 往返与清空；长历史浏览、标题吸顶和全部历史可达；按住时跟手与释放回位；动画中重新触摸；歌曲信息下拉关闭；切歌与新会话；空待播队列；短横屏；横滑；排序边缘自动滚动；窗口切换。
